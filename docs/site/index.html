Capabilities

The data management layer that AI use cases stand on

Every AI initiative stalls on the same questions: what data exists, who owns it, can we use it, how do we access it? Tabella answers them once, automatically, for every asset.

01 Manifest-driven onboarding

Owners register assets with a declarative onboarding.yaml — name, domain, owner, classification, contract, enablement. A portal form submits the exact same schema as JSON. One entry artifact, two doors.

02 Automated discovery

tabella discover crawls a source and drafts a manifest per asset it finds — for human review, never silently into the catalog. Registration stays accountable to an owner.

03 Contract verification

Declared expectations are checked against the live source at registration. A missing field, wrong type, or required-but-nullable column fails registration with a violation report — bad data never enters the catalog.

04 Catalog & governance

Assets land in OpenMetadata with tags, domains, custom properties, and contracts applied. Pluggable governance backends register assets in AWS Glue and grant Lake Formation permissions from the same descriptor.

05 Generated access layers

Every asset gets a standardized REST API — one contract for envelopes, pagination, filtering, and errors across every source. Learn one Tabella API and you have learned them all.

06 AI enablement

MCP-aligned tool manifests, semantic search over RAG-vectorized content, PII automatically excluded from agent-facing filters. Data agents can use safely, generated — not hand-built per project.

Methodology

From onboarding form to AI-ready asset

The pipeline mirrors how mature data organizations actually onboard assets — but automates every step after the form. Each stage is derived from the one before it, and everything downstream is regenerable.

01

Declare the asset data owner

The owner fills the onboarding manifest — YAML by hand or the console form. It captures identity (name, domain, owner), classification, the data contract, access policy, and which enablement artifacts to produce.

02

Introspect & verify tabella register

Tabella connects to the source, extracts the schema in canonical types, and verifies the declared contract against reality. Violations stop the pipeline with a precise report; PII markings flow into the schema.

03

Catalog openmetadata

The verified Asset Descriptor — the portable record every downstream artifact derives from — is written locally and mirrored into OpenMetadata: entity, tags, domain assignment, custom properties, contract.

04

Govern glue · lake formation

Governance backends translate the descriptor's classification and access policy into real permissions — Glue Data Catalog registration and Lake Formation grants on AWS, or any backend implementing the same interface.

05

Enable & serve generators

Generators produce the REST access layer, the MCP tool manifest, and — for text-heavy assets — the RAG pipeline: chunking, embeddings, vector index, semantic search endpoint. Restricted assets and PII fields are excluded from agent surfaces by default.

06

Observe platform

The commercial console watches the whole estate: classification coverage, contract compliance, drift detection on re-crawl, and utilization of every generated API and tool.

onboarding.yaml — the entry artifact
asset:
  name: customers
  domain: sales
  owner: sales-data@example.com
  classification: internal
source:
  connector: postgres
  uri: postgres://analytics-db:5432/retail
  native_name: public.customers
contract:
  fields:
    - {name: id, type: integer, required: true}
    - {name: email, type: string, pii: true}
enablement:
  api: true
  mcp: true
